## 一、基础需求

### 1.1 项目仓库 Code Wiki
- 分析并理解万悟（Wanwu）项目仓库
- 生成结构化的完整 Code Wiki 文档（md 文件）
- 包含：项目整体架构、主要模块职责、关键类与函数说明、依赖关系、项目运行方式

### 1.2 AI 化办公实施方案
- 公司：锅炉制造行业，国有企业
- 平台：元景万悟智能体平台（Wanwu AI Agent Platform）
- 后期需接入 ERP、MES、WPS（工作流）等系统
- 敏感数据处理：财务、人事等
- 权限设置方案
- 私有部署 vs API 模型部署的区别与选择
- 需要完整的实施方案

### 1.3 文本纠错场景（优先落地）
- 场景：体系管理手册纠错
- 手册基于体系管理文件（法规、国家标准等）人工编写，可能存在错误
- 纠错类型：引用错误、引用到错误的标准、瞎编的法规、引用到错误的数据、语法错误、逻辑错误
- 体系管理文件每年更新（法规、国家标准等）
- 需要完整的搭建步骤

## 二、模型与成本需求

### 2.1 模型选型
- 考虑后期 AI 需求，应使用更强的模型（如 GLM-5.1 或 Qwen3.6）
- 显卡选择：RTX 4090D
- 需重新计算私有化部署成本
- 需对比 API 调用成本

### 2.2 成本敏感
- 对成本非常敏感
- 需保证可扩展性
- 国企需保证数据安全
- 需要对成本、配置、部署等方向做更细的分析

### 2.3 DeepSeek API 安全性
- 使用外部 DeepSeek API + 本地数据库是否有数据泄露问题
- 需要分析风险并写入实施方案

## 三、扩展场景需求

### 3.1 焊接质检（深度学习/CV）
- 识别质检图片，判断焊接是否达标
- 图片标注后训练模型，提高质检效率
- 涉及 YOLOv8 等视觉模型

### 3.2 生产参数优化（IoT/ML）
- 采集设备使用数据
- 获取较优参数进行推荐，减少工人门槛
- 不熟练的工人可通过参数推荐提升操作质量

### 3.3 平台统一性
- 是否可以通过一个平台（万悟）进行所有工作
- 还是需要其他解决方案

## 四、架构决策需求

### 4.1 多部门多需求场景
- 很多部门的需求还没有收集
- 训练应该是一次性或固定时间训练
- 多需求且需要权限设置的场景，是否不适合训练一个大模型
- 最佳适配是否为 LLM + 知识库方案

### 4.2 持续学习能力
- 如果用大模型 + 知识库，如何保证持续学习的能力
- RAG 持续学习四层机制

### 4.3 Hermes 持续学习
- Hermes 的持续学习能力是否可以引入
- Skill、工作流在业务中有什么作用
